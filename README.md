### Warnings

- **It does not promise a permanent 100% local mode.** That does not exist today with the available access.
- The BLE window lasts **~3 minutes** per pairing; the keepalive does not extend it.
- LAN mode is **gated by the vendor cloud session**.
- The bind and the PSK are secrets of the Quectel module; they are not in the app, the cloud API or the OTA image.
- This branch exposes **test services** and a **TLS probe**; it is not production-ready.
- **Do not switch to `main`/HACS while the station points at the local broker.** `main` does not include `cloud_bridge.py`; the station would keep a dead `:8886` endpoint and drop off the network. Factory reset + Wonderfree rebind first.
- **Do not blind-fuzz `9c40`**: it is the provisioning/OTA channel, not a debug port.

> [!IMPORTANT]
> **FAKE CLOUD WITH THE PSK: THE STATION WOULD BELIEVE IT IS TALKING TO OUKITEL AND WOULD KEEP EMITTING. THIS REQUIRES EXTRACTING THE PSK VIA UART / JTAG / BKFIL. TODAY IT IS NOT SOLVED.**

## What “zero cloud” means

The goal is for the station to talk to a local MQTT broker and to the LAN without depending on `iot-south.acceleronix.io`.

This branch implements:

1. **BLE provisioning** (`0x7010` over characteristic `9c40`) to tell the station which Wi-Fi to join and which endpoint to use.
2. **Fake cloud** (`cloud_bridge.py`): an MQTT broker on port `8886` that answers like the QuecThing cloud.
3. **Direct LAN** (`local_session.py`): TCP `6607` with handshake and AES encryption using the device `authKey`.
4. **Diagnostics**: GATT dump, hex logs, flight recorder, test services and a TLS probe.

The station accepts the local broker and streams telemetry, but **only while the BLE provisioning link remains open** or while the vendor cloud keeps the session alive. The bind/PSK is still the wall.

## What works

- **Cloud + LAN** in `main` v1.5.7: local telemetry with the cloud supporting the bind.
- **Local broker** on `:8886` during the BLE window: `CONNECT`, `SUBSCRIBE`, telemetry and entities.
- **LAN `6607`** with the correct `authKey` while the vendor cloud is alive.
- **Factory reset** as the only re-entry point to provision again.
- **Full diagnostics** of BLE, MQTT, LAN and cloud.

## What does not work

- **Permanent mode without cloud or BLE.** The module cuts the UART stream when BLE closes.
- **Fixed Wi-Fi icon** without completing the vendor bind.
- **LAN without cloud.** Cutting the WAN stops the stream within seconds.
- **Local bind from the app.** `0x7066` is an `emptyList()`; the app ignores `0x7014`; `0xFFFE` is generated by the module after the cloud bind.
- **TLS PSK.** It is a per-device secret in the module NVM.
- **Firmware over OTA.** No plan is assigned, and the PSK is not in the image.

## Discarded hypotheses

- A GATT keepalive extending the BLE window.
- `0x7066` with tags or `0xFFFE` completing the bind.
- `0x7014` 65534 being enough for the icon.
- MCC 460 being the main blocker (the stale Wi-Fi password was).
- The PSK being in the APK, the cloud API or the OTA image.
- `0x7055` reconfiguring an already-bound station without the reset certificate.

## Risks and limits

- **Test services** (`ble_disconnect`, `bridge_send`) and the **TLS probe on 18883** must not be used in production.
- **Blind fuzzing of `9c40`** can leave the module in DFU, erase its configuration or brick it; it was not done and is not recommended.
- The **keepalive** and **periodic acks** write to the provisioning channel; they have not shown any benefit.
- This branch does not include `auth_refresh.py`, `provision_frame.py` or the unit tests from the clean proposal; those live outside this branch.
- No UART/JTAG access and no physical BLE sniffer were available.

## Manual installation

1. Back up `config/custom_components/oukitel`.
2. Copy this `custom_components/oukitel` folder into Home Assistant.
3. Restart Home Assistant.
4. Configure the integration in `zero_cloud` mode and use `mqtt://<HA_IP>:8886`.
5. BLE provisioning needs a **Bluetooth proxy** (ESPHome) and the IoT button to open the pairing window.

> HACS does not install branches directly. To test this branch, copy the folder manually or publish a pre-release with its own tag.

### Requirements

- Home Assistant 2024.1+.
- `pycryptodome>=3.18.0`.
- Local MQTT broker on `8886` (started by the integration).
- Bluetooth proxy for BLE provisioning.
- The station on the same network as Home Assistant.
