# Protocol reference

All values below were observed on a P2001 Plus (`productKey p11wN7`,
`deviceKey ecb5…`) with Wonderfree 3.7.5 and Home Assistant.

## 1. BLE frames

### 1.1 Framing

```
AA AA | body_len (2, BE) | checksum (1) | pid (2, BE) | cmd (2, BE) | payload
```

- `body_len` = bytes after the length field (checksum + pid + cmd + payload).
- `checksum` = sum of all bytes from `pid` to the end, modulo 256.
- `payload` is byte-stuffed: `0xAA` becomes `0xAA 0x55`.
- Multi-byte integers are big-endian.

### 1.2 TTLV

| Type | Meaning | Encoding |
|---|---|---|
| 0 | false | 16-bit header |
| 1 | true | 16-bit header |
| 2 | number | header + signed integer |
| 3 | string | header + 16-bit length + UTF-8 bytes |
| 4 | struct | header + 16-bit count + nested TTLV |
| 5 | bytes | header + 16-bit length + raw bytes |

Header: `(tag << 3) | type`.

## 2. `0x7010` provisioning

Command `28688`, packet id `1000`, characteristic `9c40`.

| Tag | Type | Meaning | Notes |
|---|---|---|---|
| 1 | string | Wi-Fi SSID | |
| 2 | string | Wi-Fi password | |
| 11 | number | Timeout (seconds) | The port belongs to the tag 13 URL; the APK builders confirm tag 11 is `time` |
| 12 | number | MCC | 460 in the original code; 214 tested in Spain |
| 13 | string | Endpoint URL | `mqtt://host:8886`, `mqtts://host:8883` |

### 2.1 No-endpoint mode

Endpoint `""`, `"none"` or `"lan"` → only tags 1 and 2. The station joins Wi-Fi
and opens LAN `6607`.

### 2.2 Example structure

```
AA AA 00 xx CS PP PP 70 10
  00 0B 00 07 "OUKITEL"
  00 13 00 0C "<password>"
  00 5A 00 3C               # tag 11, timeout 60
  00 6B 00 25 "mqtts://iot-south.acceleronix.io:8883"
  00 62 00 D6               # tag 12, MCC 214
```

The password and real host are redacted here.

## 3. `0x7011` response

Command `28689`.

| Tag | Type | Meaning |
|---|---|---|
| 4 | bool | Accepted/flag |
| 5 | number | Protocol/status value (observed 30) |
| 7 | string | Product key (`p11wN7`) |
| 8 | string | Device key (`ecb50a34ab76`) |
| 9 | string | `bindingCode` (empty on a virgin device) |

The `bindingCode` is **not** the TLS-PSK.

## 4. `0x7014` progress

Command `28692`.

| Code | Meaning |
|---|---|
| 16 / 0x0010 | Scanning for router |
| 32 / 0x0020 | Connecting to router |
| 48 / 0x0030 | Cloud authenticating |
| 49 / 0x0031 | Cloud authenticating |
| 64 / 0x0040 | Cloud login |
| 80 / 0x0050 | Cloud resting |
| 96 / 0x0060 | Cloud binding |
| 65534 / 0xFFFE | Success |
| 65535 / 0xFFFF | Failure |

The app contains `if (cmd == 28692) return;`, i.e. it ignores `0x7014`.
The `0xFFFE` success code is generated by the module after the cloud bind.

## 5. `0x7066`, `0x7036`, `0x7055`

| Command | Direction | Observed payload | Meaning |
|---|---|---|---|
| `0x7066` (28774) | App → module | `emptyList()` | Ack for cloud login/bind; no tags |
| `0x7036` (28726) | Module → app/LAN | TTLV `{1: 0}` | Write ACK / bind query |
| `0x7055` (28757) | App → module | Reconfiguration request | Requires a reset certificate from the cloud |

Sending `0x7066` with custom tags or `0xFFFE` does not complete the bind.

## 6. GATT table

| Service | Characteristics |
|---|---|
| `0x1800` Generic Access | `0x2A00` (read), `0x2A01` (read), `0x2AC9` (read) |
| `0x1801` Generic Attribute | `0x2A05` (indicate), `0x2B29` (read/write), `0x2B2A` (read) |
| `0x180A` Device Information | `9c40` (write/notify) |

There is **no DFU/UART/OTA service**. The OTA protocol uses `9c40`.

## 7. TLS-PSK

ClientHello observed from the module:

- TLS 1.2
- No SNI
- No certificate suites
- Cipher suites:
  - `0x008D` `TLS_PSK_WITH_AES_256_CBC_SHA`
  - `0x00AE` `TLS_PSK_WITH_AES_128_CBC_SHA256`
  - `0x008C` `TLS_PSK_WITH_AES_128_CBC_SHA`
  - `0x00FF` SCSV

The 18 tested candidates were derived from `authKey`, `bindingCode`,
`deviceKey`, `productKey`, the domain secret, and MD5/SHA-256/HMAC
combinations. All failed at the cipher step.

## 8. LAN protocol (`6607`)

### 8.1 Framing

Same SLIP-like framing as BLE:

```
AA AA | body_len | checksum | pid | cmd | payload
```

Payload is AES-128-CBC encrypted after the handshake.

### 8.2 Handshake

1. `CMD_HELLO`
2. `CMD_NONCE` → 16-byte nonce (IV)
3. `CMD_LOGIN` with token derived from `authKey`
4. `CMD_LOGIN_OK` (`result=0`)

### 8.3 Commands

| Command | Meaning |
|---|---|
| 16 | Hello |
| 17 | Read |
| 19 | Write |
| 20 | Telemetry |
| 21 | Telemetry/notification |
| 35 | Heartbeat/keepalive |
| 36 | Write ACK / bind |
| 38 | Heartbeat/keepalive |

## 9. MQTT topics

| Direction | Topic |
|---|---|
| Uplink | `q/2/d/<pk><dk>/bus` |
| Downlink | `q/1/d/<pk><dk>/+` |

Variants: `sys`, `bus_`, `sys_`.

## 12. Notes

- Tag 11 is the provisioning timeout; the port belongs to the tag 13 URL.
  Older notes that called it a port were wrong; see [PITFALLS.md](PITFALLS.md).
- MCC 460 vs 214 was not isolated; the stale Wi-Fi password was the confirmed
  blocker.
- The `bindingCode` is not the PSK.
- The PSK is per-device NVM, not in the firmware image.
